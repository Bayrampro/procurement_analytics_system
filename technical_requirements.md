# Техническое задание  
## на разработку информационной системы  
**«Анализ торговых площадок в сфере закупок»**

---

## 1. Общие сведения

### 1.1 Назначение системы
Информационная система предназначена для **сбора, хранения, анализа и визуализации данных о закупках**, размещённых на электронных торговых площадках, с целью получения аналитической информации и поддержки принятия решений.

---

### 1.2 Область применения
Система может использоваться:
- для аналитического анализа рынка закупок  
- в учебных и исследовательских целях  
- специалистами в сфере закупок  

---

### 1.3 Пользователи системы
- аналитик  
- исследователь  
- студент  

Авторизация пользователей **не требуется**.

---

## 2. Функциональные требования

### 2.1 Импорт данных
Система должна:
- загружать данные о закупках из CSV-файлов  
- выполнять проверку корректности данных  
- сохранять импортированные данные в базу данных  

CSV-файл является **первичным источником данных**.

---

### 2.2 Хранение данных
Система должна:
- хранить данные о закупках в локальной базе данных  
- обеспечивать доступ к данным для аналитической обработки  
- поддерживать обновление и удаление записей  

---

### 2.3 Просмотр списка закупок
Система должна:
- отображать список закупок в виде таблицы или списка  
- отображать основные сведения о закупке:
  - торговая площадка  
  - заказчик  
  - предмет закупки  
  - стоимость  
  - статус  

---

### 2.4 Фильтрация и поиск
Система должна поддерживать фильтрацию данных:
- по торговой площадке  
- по категории закупки  
- по статусу  
- по диапазону цен  
- по дате публикации  

---

### 2.5 Аналитика закупок
Система должна выполнять аналитическую обработку данных и отображать:
- количество закупок по торговым площадкам  
- общую сумму закупок  
- распределение закупок по статусам  
- динамику закупок по времени  
- распределение закупок по категориям  

---

### 2.6 Визуализация данных
Система должна:
- отображать результаты анализа в виде:
  - столбчатых диаграмм  
  - линейных графиков  
  - круговых диаграмм  
- автоматически обновлять визуализацию при изменении фильтров  

---

### 2.7 Детальный просмотр закупки
Система должна:
- отображать подробную информацию о выбранной закупке  
- обеспечивать просмотр всех атрибутов записи  

---

## 3. Требования к пользовательскому интерфейсу

### 3.1 Общие требования
Интерфейс системы должен быть:
- интуитивно понятным  
- визуально аккуратным  
- логически структурированным  

---

### 3.2 Требования к дизайну
Интерфейс должен:
- использовать единый стиль оформления  
- применять визуальную иерархию элементов  
- использовать читаемые шрифты и корректные отступы  
- обеспечивать наглядное отображение аналитических показателей  
- корректно отображать таблицы и графики на различных экранах  

---

### 3.3 Пользовательский опыт (UX)
Интерфейс должен:
- обеспечивать быстрый доступ к ключевой аналитике  
- минимизировать количество действий пользователя  
- визуально выделять ключевые показатели и метрики  

---

## 4. Нефункциональные требования

### 4.1 Технические требования
- язык программирования: **Dart**  
- фреймворк: **Flutter**  
- база данных: **SQLite**  
- целевая платформа: **Windows**  

---

### 4.2 Требования к производительности
- корректная работа с набором данных до **1000 записей**  
- время отклика интерфейса — не более **1 секунды**  

---

### 4.3 Требования к надёжности
- корректная обработка ошибок при импорте данных  
- устойчивость приложения при некорректных входных данных  

---

## 5. Архитектура системы

Система должна включать следующие модули:
1. Модуль импорта данных  
2. Модуль хранения данных  
3. Модуль аналитической обработки  
4. Модуль визуализации  
5. Пользовательский интерфейс  

---

## 6. Основные экраны системы

1. **Главный экран (Dashboard)**  
   - ключевые показатели  
   - аналитические графики и диаграммы  

2. **Список закупок**  
   - таблица данных  
   - фильтры и поиск  

3. **Экран аналитики**  
   - детальные аналитические диаграммы  
   - сравнительный анализ торговых площадок  

4. **Экран импорта данных**  
   - загрузка CSV-файла  

5. **Экран деталей закупки**

---

## 7. Автоматизация сборки и развёртывания (CI/CD)

### 7.1 Общие требования
В рамках проекта должна быть реализована автоматизация процесса сборки и упаковки приложения.

---

### 7.2 Сборка приложения
Система сборки должна:
- автоматически выполнять сборку Windows-версии приложения Flutter  
- формировать исполняемый файл (`.exe`)  

---

### 7.3 Создание установочного пакета
Для распространения приложения должен быть реализован установочный файл:
- формат установщика: **`.exe`**  
- средство создания: **Inno Setup**  
- установщик должен:
  - копировать файлы приложения  
  - создавать ярлык на рабочем столе  
  - добавлять запись в список установленных программ  

---

### 7.4 CI/CD
Процесс CI/CD должен:
- автоматически запускаться при изменении исходного кода  
- выполнять сборку приложения  
- формировать установочный файл  
- сохранять установщик как артефакт сборки  

---

## 8. Ограничения и допущения
- допускается использование тестовых данных  
- интеграция с реальными торговыми площадками не требуется  
- система реализуется в виде прототипа  

---

## 9. Ожидаемый результат
Результатом выполнения работы является **информационная система**, обеспечивающая загрузку данных о закупках, их аналитическую обработку, визуализацию результатов анализа, а также автоматизированную сборку и упаковку приложения в установочный файл.
